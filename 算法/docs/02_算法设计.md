# 02 算法设计

## 1. 总体框架

```
┌─────────────────────────────────────────────────────────────┐
│ 夜间（23:30–06:30）                                          │
│   静态 MILP（OR-Tools CP-SAT）                                │
│   决策：各点净调入/调出 y_i + 单车间路径                        │
│   目标：次日目标库存偏差 + 行驶成本                             │
│   输出：次日 06:30 初始库存                                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ 初始库存
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 日内（06:30–23:30，10 min/步，102 步）                         │
│   MDP 环境（Gymnasium）                                       │
│   状态：库存/目标偏差/可用车/卡车/时段/脉冲/预算                 │
│   动作：(mode, station, tier)                                 │
│   奖励：−[E_agent, E_env, T_truck, P_inc]                     │
│   求解：MaskablePPO（SB3）                                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ 逐日评估
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 评价：8 项指标 + 6 条基线 + 消融 / 敏感性 / 泛化                │
└─────────────────────────────────────────────────────────────┘
```

双层固定点迭代（可选）：给定券额 `p` → 仿真用户响应 → 训练 PPO → 按未满足率更新 `p` → 重复。

## 2. 环境实现（`src/bike_sched/env/campus_env.py`）

### 2.1 状态向量

| 分量 | 维度 | 说明 |
|---|---|---|
| `n_i / L_i` | N | 库存占容量比 |
| `(n_i − target_i)/L_i × 0.5 + 0.5` | N | 相对目标偏差（归一化） |
| `n_i^avail / L_i` | N | 可用车占比 |
| `truck.load / C` | 1 | 载量 |
| truck position one-hot | N | 位置 |
| busy flag | 1 | 是否忙碌 |
| `sin(2πt/1440), cos(2πt/1440)` → [0,1] | 2 | 时段周期 |
| pulse flag, pulse phase | 2 | 是否脉冲、脉冲内相位 |
| day type one-hot | 2 | 工作日/周末 |
| last truck mode one-hot | 3 | none/pickup/dropoff |
| remaining budget ratio | 1 | 剩余券预算 |

总维度 `4N + 12`（N=12 → 60）。

### 2.2 动作编码

```
a = mode × (N×2) + station × 2 + tier
mode ∈ {0 wait, 1 truck, 2 coupon}
tier ∈ {0,1}
```

- 搬运：`tier 0/1` → 10/20 辆
- 发券：`tier 0/1` → 0.5/1.0 元

**方向自动判定**（不交给智能体学习）：

```
缺车临界（n_avail < δL）→ 调入（从车上卸下）
满位临界（L−n < δL）   → 调出（装车）
```

**取/放交替**：连续同向搬运非法（L3 的交替规则），迫使卡车"先收后送"。

### 2.3 动作掩码

精确扁平掩码，长度 `3·N·2`：

- `mode=0` 永远合法；
- `mode=1`：卡车不忙、点位临界、可达、数量 > 0、满足交替；
- `mode=2`：点位有可用车且非缺车临界、预算足够、券额可承受。

无任何合法动作时，`wait` 仍合法（`_is_valid(0,·,·)=True`）。

### 2.4 单步流程

```
1. 解码动作；非法则回退为 wait
2. 搬运动作：改变库存/载量，设置忙碌步数，记录作业时间
3. 发券动作：设置本步券额
4. 需求实现：D = 真实需求 × 对数正态噪声 × 周末系数
5. 反事实：同需求、无搬运/发券、保留自然移步 → cf_short
6. 实际：借车 → 移步再分配 → 还车 → 还车短缺
7. 奖励：E_env = min(actual, cf)，E_agent = max(0, actual−cf)
8. 更新库存、指标、步数
```

### 2.5 奖励

```
r = −[ w1·E_agent/S1 + w2·E_env/S1 + w3·T_truck/S2 + w4·P_inc/S3 ] × reward_scale
```

默认：`w1=1.0, w2=0.3, w3=0.2, w4=0.2`；`S1=10, S2=30, S3=10`；`reward_scale=10`。

> 权重是政策偏好，不是物理参数。提高 `w2` 会更重视服务率，提高 `w3` 会更吝啬搬运。论文中应报告一组权重下的结果，并做权重敏感性。

## 3. PPO（`src/bike_sched/rl/ppo.py`）

### 3.1 为什么用 SB3

- 用户指定 Stable-Baselines3；
- `sb3-contrib` 的 `MaskablePPO` 原生支持动作掩码；
- `MlpPolicy + net_arch=[128,128]` 提供**共享主干 + 策略/价值双头**，与 L3 的共享网络结构一致。

### 3.2 超参数

| 项 | 取值 | 说明 |
|---|---|---|
| 算法 | MaskablePPO | 动作掩码 |
| 策略 | MlpPolicy | 共享主干 |
| `net_arch` | [128, 128] | 共享层，后接策略/价值头 |
| `n_steps` | 1024 | 约 10 个 episode/更新 |
| `batch_size` | 256 | — |
| `learning_rate` | 3e-4 | — |
| `gamma` | 0.95 | 10 min 步长，有效视野约 20 步 |
| `gae_lambda` | 0.95 | — |
| `clip_range` | 0.2 | — |
| `ent_coef` | 0.01 | 探索 |
| `vf_coef` | 0.5 | — |
| `max_grad_norm` | 0.5 | — |
| 设备 | CPU | 本机无 GPU |

### 3.3 训练协议

- 一个 episode = 模拟一天（102 步）；
- 每个 episode 从需求分布中抽样噪声，模拟不同日；
- 训练 / 验证 / 测试按随机种子划分（当前用不同 seed 模拟不同日；真实数据到位后改为**时间上不相交**的划分）；
- 评估用 3 个未见过的 seed，报告均值与标准差；
- 最终模型保存在 `outputs/ppo_*/ppo_seed*.zip`。

### 3.4 与论文的差异

| 论文（L3） | 本实现 | 原因 |
|---|---|---|
| 双头：节点 + 数量 | 扁平 Discrete（可选 MultiDiscrete） | SB3 下精确掩码更稳；多头形式保留为配置项 |
| 多卡车、每车单独动作 | 单卡车 | 校园规模 12 点 × 1 车（文档 10.3） |
| 状态含小时/星期/月份 one-hot | 时段 sin/cos + 星期类型 | 降低维度，保留周期信息 |
| 需求为真实数据集 | 合成/观测需求 | 数据未采集 |
| SA 扰动动作序列 | SA 扰动策略参数 | 可运行性；论文须说明 |

## 4. 基线（`src/bike_sched/baselines/`）

| 基线 | 实现 | 作用 |
|---|---|---|
| `noop` | 永远 wait | 下界 |
| `random` | 从合法动作均匀采样 | 检验策略是否优于随机 |
| `pure_truck` | 贪心：就近 + 最临界 + 最大档 | 现实运营做法 |
| `pure_coupon` | 贪心：最盈余点位 + 最大券额 | 激励通道单独价值 |
| `greedy` | 搬运优先，否则发券 | 协同贪心 |
| `sa` | 扰动贪心策略参数（δ 偏移、档位、优先通道） | 元启发式对照 |

贪心评分：

```
score_truck(s) = max(缺车缺口, 满位缺口) / (1 + travel/500)
score_coupon(s) = (n_s − target_s) + 0.1·D_s
```

SA 的评估目标与 PPO 相同（整日累计奖励），评估种子固定以降低噪声。

## 5. 夜间静态 MILP（`src/bike_sched/night/milp.py`）

### 5.1 决策变量

| 变量 | 含义 |
|---|---|
| `y_i ∈ [−C, C]` | 点位净调入（正）/调出（负） |
| `u_i ∈ [0, L_i]` | 调度后库存 |
| `x_ij ∈ {0,1}` | 卡车是否从 i 行驶到 j |
| `load_i ∈ [0, C]` | 到达 i 后的载量 |
| `order_i` | MTZ 顺序变量 |
| `dev_i ≥ 0` | `|u_i − target_i|` 的线性化 |

### 5.2 约束

```
u_i = n_i^night + y_i
Σ_i y_i = 0
y_depot = 0
y_i ≤ C·visited_i,  y_i ≥ −C·visited_i
Σ_j x_ij = Σ_j x_ji ≤ 1（每个站点至多进出一次）
load_j = load_i − y_j （沿路径）
load_depot = 0（空载出发、空载返回）
order_j ≥ order_i + 1 − N·(1−x_ij)（MTZ 消子环）
```

### 5.3 目标

```
min  w_inv · Σ_i dev_i + c_travel · Σ_ij (d_ij / v) · x_ij
```

默认 `w_inv=10`、`c_travel=1 元/min`。

### 5.4 求解

OR-Tools CP-SAT，`max_time_in_seconds=30`，4 线程。12 点位规模通常秒级求得最优。

## 6. 双层固定点迭代（`src/bike_sched/bilevel.py`）

```
scale ← 1.0
repeat:
    cfg_i ← cfg with coupon_tiers = base × scale
    model ← train_ppo(cfg_i)
    evaluate(model) → unmet_rate
    if unmet_rate > target: scale × 1.25
    elif unmet_rate < target/2: scale × 0.8
    else: break
```

说明：完整版应求下层均衡；本实现用整日仿真替代，符合文档"结合仿真系统的启发式"定位。

## 7. 训练与评估流程

### 7.1 训练

```bash
python scripts/train_ppo.py --timesteps 200000 --seed 0 --out outputs/ppo
```

### 7.2 评估

```bash
python scripts/evaluate.py --model outputs/ppo/ppo_seed0 --seeds 101,102,103
```

### 7.3 主实验

```bash
python scripts/run_experiments.py --exp main --model outputs/ppo/ppo_seed0
```

输出：

- `outputs/experiments/main_summary.csv`：各策略 8 项指标均值/标准差
- `outputs/experiments/main_bar.png`：服务率/短缺/成本/趟次对比图

### 7.4 当前占位结果（20 万步，2 个评估种子）

| 策略 | 服务率 | 总短缺 | 单位成本 | 搬运趟次 |
|---|---|---|---|---|
| noop | 0.9928 | 241.7 | 0.0000 | 0 |
| random | 0.9928 | 227.0 | 0.0269 | 10 |
| pure_truck | 1.0000 | 140.9 | 0.1199 | 48 |
| pure_coupon | 0.9931 | 240.2 | 0.0084 | 0 |
| greedy | 1.0000 | 141.7 | 0.1208 | 48 |
| sa | 1.0000 | 143.2 | 0.1152 | 50 |
| **ppo** | **0.9994** | **184.4** | **0.0311** | **13** |

解读：PPO 用约 1/4 的搬运成本，把服务率从 99.28% 提升到 99.94%；与纯搬运相比，用 13 趟 vs 48 趟换来略高的短缺（184 vs 141）。这正是奖励函数中"服务—成本"权衡的体现。

> 以上为占位数据结果，不能作为论文实证结论。

## 8. 复现要点

1. 固定随机种子（`project.seed`、`ppo.seeds`）；
2. 训练与评估使用不同 seed；
3. 评估至少 3 个种子，报告均值 ± 标准差；
4. 所有图由脚本生成，不手工改数；
5. 论文中明确区分"占位结果"与"实测结果"。
