## 1. 主实验：六条基线 + PPO

### 1.1 对照策略

| 策略 | 说明 | 作用 |
|---|---|---|
| `noop` | 永远不调度 | 下界 |
| `random` | 合法动作均匀采样 | 检验策略是否优于随机 |
| `pure_truck` | 就近 + 最临界 + 最大档 | 现实运营做法，主对照 |
| `pure_coupon` | 最盈余点位 + 最大券额 | 激励通道单独价值 |
| `greedy` | 搬运优先，否则发券 | 协同贪心 |
| `sa` | 扰动贪心策略参数的模拟退火 | 元启发式对照 |
| `ppo` | MaskablePPO | 本文方法 |

### 1.2 指标

八项指标（`docs/01_建模说明.md` 第 8 节）：

1. 借车短缺
2. 还车短缺
3. 搬运趟次
4. 搬运作业时间
5. 单位服务成本
6. 点供需失衡指数
7. 流供需失衡指数
8. 智能体导致短缺 / 环境赤字

### 1.3 评估协议

- 评估种子：至少 3 个（默认 101/102/103），训练时未使用；
- 报告均值 ± 标准差；
- 真实数据到位后改为**时间上不相交**的留出日（如训练 4 天、测试第 5 天）。

### 1.4 运行

```bash
python scripts/run_experiments.py --exp main --model outputs/ppo/ppo_seed0 --seeds 101,102,103
```

输出：

- `outputs/experiments/main_summary.csv`
- `outputs/experiments/main_rows.csv`
- `outputs/experiments/main_bar.png`

### 1.5 当前占位结果

| 策略 | 服务率 | 总短缺 | 单位成本 | 搬运趟次 |
|---|---|---|---|---|
| noop | 0.9928 | 241.7 | 0.0000 | 0 |
| random | 0.9928 | 227.0 | 0.0269 | 10 |
| pure_truck | 1.0000 | 140.9 | 0.1199 | 48 |
| pure_coupon | 0.9931 | 240.2 | 0.0084 | 0 |
| greedy | 1.0000 | 141.7 | 0.1208 | 48 |
| sa | 1.0000 | 143.2 | 0.1152 | 50 |
| **ppo** | **0.9994** | **184.4** | **0.0311** | **13** |

**预期结论（待真实数据验证）**：

- PPO 在"服务率—成本"曲线上位于 noop 与 pure_truck 之间，且更靠近"低成本、高服务"的帕累托前沿；
- 纯激励单独作用有限（月卡制削弱价格激励，γ 是关键调节变量）；
- 搬运仍是校园场景的主要手段，激励用于短课间窗口的边际补充。

## 6. 精确解对照（小规模）

### 6.1 目的

RL 无最优性保证。用极小规模实例求精确解，报告 PPO 的次优性 gap。

### 6.2 设置

- 3 个 P 点（1 宿舍 + 1 教学 + 1 食堂）；
- 4 个决策步；
- 车载量 8；
- 仅搬运（不含发券），确定性需求；
- 状态空间可枚举，用动态规划求最优。

### 6.3 运行

```bash
python scripts/exact_gap.py
```

输出：`outputs/exact/exact_gap.json`，含：

- 精确最优累计奖励；
- 贪心策略累计奖励；
- PPO 累计奖励；
- `gap = (optimal − policy) / |optimal|`。

### 6.4 当前占位结果

实例：P01（宿舍）/ P04（教学）/ P08（食堂），容量各 12，初始各 8，车载量 8，4 步，关闭发券与需求噪声。

| 策略 | 累计奖励 | 相对最优 gap |
|---|---|---|
| 精确 DP（最优） | −2.5836 | 0% |
| 贪心（纯搬运） | −3.0294 | 17.26% |
| PPO（3 万步小规模训练） | −2.5836 | **0%** |

解读：

- PPO 在该小规模实例上达到精确最优，说明动作掩码、奖励与训练链路正确；
- 贪心因"就近 + 最大档"的短视，产生 17.3% 的次优；
- 该结果只说明**小规模可学**，不能外推到 12 点位全天场景。

### 6.5 解读

- gap < 5%：策略接近最优；
- gap 5–15%：可接受，需说明状态空间/训练规模限制；
- gap > 15%：检查奖励设计、动作掩码或训练不足。
