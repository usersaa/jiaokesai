## 3. 需求侧（`src/bike_sched/demand.py`）

### 3.1 真实需求与观测需求的分离（L4）

历史订单是供给约束下的观测值，会系统性低估真实需求。本模型不直接使用订单量：

```
真实需求  D_i^b(t) = 由课程安排、功能分布与吸引量推算
观测订单  O_i^b(t) = min{ D_i^b(t), n_i^avail(t) }     ← 供给截断
```

供给截断在 `supply.borrow()` 中实现，保证"缺车"产生可计量损失。

### 3.2 七脉冲需求

```
D_i^b(t) = B_i · h(t) + Σ_{r∈R} A_i^r · φ((t − t_r) / w_r)
```

代码对应：

```python
D = baseline * smoothing(t)
for r in pulses:
    D += A[:, r] * kernel((t - peak_r) / width_r)
```

其中：

- `B_i = baseline_rate_per_hour × (Δt/60) × attr_norm_i`
- `A_i^r = baseline_rate_per_hour × (Δt/60) × pulse_gain × intensity[func_i][r] × attr_norm_i`
- `attr_norm_i = A_i / mean(A)`
- `φ(x) = exp(−x²/2)`（高斯，默认）或 `exp(−|x|)`（指数）
- `h(t) = smooth_night`（t < 08:00 或 t ≥ 22:30），否则 `smooth_day`

**功能—脉冲矩阵** `intensity[func][r]` 是需求模型的核心参数表（`configs/default.yaml`）。它表达"哪类点位在哪个脉冲净流出"：

- 宿舍：P1、P4 高（去上课）
- 教学：P3、P6、P7 高（下课离开），P2、P5 中（换教室）
- 食堂：各脉冲都低（主要是目的地）
- 图书馆、校门、运动场：中等

### 3.3 OD 分布（L5）

```
q_ij(t) = D_i^b(t) · [A_j · f(d_ij)] / Σ_{k≠i} [A_k · f(d_ik)]
```

距离衰减（默认对数正态）：

```
f(d) = exp( −(ln(max(d,1)/d0))² / (2σ²) )
```

代码：`DemandModel.od_probabilities()` 返回行和为 1 的 `P[i,j]`，`od_matrix(D) = D[:,None] * P`。

校园内无机动车拥堵、限速统一，按文档说明**略去拥堵指数**（L5 的第二因素）。

### 3.4 需求随机性

训练时对每步每点乘对数正态噪声：

```
D̃_i(t) = D_i(t) · exp(ε − σ²/2),  ε ~ N(0, σ²)
```

`noise_cv = σ`（默认 0.15）。周末需求乘 `weekend_factor`（默认 0.60）。

## 4. 供给侧（`src/bike_sched/supply.py`）

### 4.1 库存演化

```
n_i(t+1) = n_i(t) + r_i(t) − b_i(t) − b_i^extra(t) + min(r_i^total(t), free_i(t))
```

代码顺序：

1. 搬运动作先改变 `n_i`（当步末完成）；
2. `b_i = min(D_i, n_i^avail)`；
3. 移步承接 `b_i^extra`（见第 5 节）；
4. `r_i = Σ_j Q_ji`（校园骑行 < 10 min，忽略时滞）；
5. `free_i = L_i − n_i + b_i + b_i^extra`；
6. `accepted = min(r_i^total, free_i)`，超出部分为还车短缺。

### 4.2 可用车

```
n_i^avail = round(n_i · ρ_soc)
```

不刻画单车级电量；换电由运营商按固定路线执行，视为外生过程。

### 4.3 搬运作业时间（L3 式(5)）

```
τ_ij = d_ij / v_truck + |q| · t_load
```

- 单步可用作业时间：`T_avail = Δt − T_swap`
- 忙碌步数：`ceil(τ_ij / Δt)`
- 搬运方向由点位状态自动判定：缺车临界 → 调入；满位临界 → 调出
- 取/放交替：`alternate_pick_drop=true` 时，连续同向动作非法（L3 的交替规则）

### 4.4 短缺

```
借车短缺（移步前）  e_i^b,origin = D_i − b_i
还车短缺            e_i^r = max(0, r_i^total − free_i)
借车短缺（最终）    e_i^b = max(0, e_i^b,origin − Σ_j M_ij)
```

> 最终借车短缺扣除了成功移步到邻点取车的人数，避免"服务率 100% 却报缺车"的口径错误。

## 5. 下层用户选择（`src/bike_sched/choice.py`）

依据 L2 式(16)(17)。

### 5.1 移步意愿

```
κ(Δw) = exp(−λ · Δw)
```

`Δw` 为步行时间（min），`λ` 越大越不愿移步。

### 5.2 竞争型取车概率

```
f_j = n_j^avail / (n_j^avail + N_j)
```

`N_j` 为同时到达 j 的用户数（代码用该步需求 `D_j` 作代理）。

### 5.3 激励的作用路径

```
Δw_eff = max(0, Δw − p_j / VOT)
κ_eff  = exp(−λ · Δw_eff)
```

激励不直接移动车辆，只降低等效步行成本。

### 5.4 月卡与单次用户

月卡用户边际成本≈0，价格激励无效。代码按比例混合：

```
w_ij = [(1−γ)·κ(Δw_ij) + γ·κ(Δw_ij − p_j/VOT)] · f_j
```

### 5.5 再分配

```
M_ij = unmet_i · w_ij / Σ_k w_ik
extra_j = min(Σ_i M_ij, n_j^avail − b_j)
e_i^b = max(0, unmet_i − Σ_j M_ij)
券支出 = Σ_j p_j · γ · Σ_i M_ij
```

`extra_j` 受目标点剩余可用车限制；超出部分按比例回缩 `M`，保证人次守恒。

## 6. 上层目标与约束

### 6.1 日内目标（L3 式(6)(10)）

```
min Z_day = Σ_t [ ω1·E_agent(t) + ω2·E_env(t) + ω3·T_truck(t) + ω4·P_inc(t) ]
```

| 项 | 含义 | 代码 |
|---|---|---|
| E_agent | 智能体导致的短缺 | `agent_short = max(actual − cf, 0)` |
| E_env | 环境赤字（不可避免） | `env_def = min(actual, cf)` |
| T_truck | 运维车作业时间 | `truck_time` |
| P_inc | 激励支出 | `coupon_cost` |

**反事实分解**：`cf` 为"同需求、不做搬运/发券、但保留自然移步"的短缺。它把"策略可改进的空间"与"需求本身有多难"分开。

### 6.2 夜间目标（L1 式(1)）

```
min Z_night = Σ_i w_i·|u_i − n_i^target| + Σ_{(i,j)} c_travel·d_ij/v
```

夜间 23:30–06:30 为零需求窗口；运维车从车场出发、返回车场，返回时须空载。

### 6.3 约束

| 编号 | 约束 | 代码位置 |
|---|---|---|
| C1 | 单次装卸 ≤ 车载量 C | `_truck_qty` |
| C2 | 单步作业时间 ≤ Δt − T_swap | `_truck_reachable` |
| C3 | n_i ≤ L_i（软，满位产生还车短缺） | `return_shortage` |
| C4 | 日激励预算 ≤ P_daily | `coupon_used` / `budget` |
| C5 | 车辆总数守恒 | 库存更新 + 搬运 |
| C6 | 券额 ∈ {0.5, 1.0} 元 | `coupon_tiers_yuan` |

## 7. MDP 形式化（`src/bike_sched/env/campus_env.py`）

### 7.1 状态

```
s_t = { n_i/L_i, (n_i − n_i^target)/L_i, n_i^avail/L_i }_{i∈S}
    ∪ { 运维车载量/C, 位置 one-hot, 忙标志 }
    ∪ { 时段 sin/cos, 脉冲标志, 脉冲相位, 星期类型 one-hot }
    ∪ { 上一步搬运方向 one-hot, 剩余券预算比例 }
```

维度：`4N + 12`（N=12 时为 60），全部归一化到 [0,1]。

### 7.2 动作

```
a_t = (mode, station, tier)
mode   ∈ {0 wait, 1 truck, 2 coupon}
station ∈ {0,…,N−1}
tier   ∈ {0,1}  → 搬运 {10,20} 辆；发券 {0.5,1.0} 元
```

**动作空间实现**：

- `discrete`（默认）：`Discrete(3·N·2)`，配合精确扁平掩码；
- `multidiscrete`：`MultiDiscrete([3,N,2])`，按维度掩码（论文多头形式）。

选择 `discrete` 的原因：MultiDiscrete 的掩码只能按维度取并集，无法表达"某点位只对发券合法、对搬运非法"，会产生大量非法组合；精确扁平掩码消除了这一问题。

### 7.3 剪枝（L3 式(11)）

```
缺车临界：n_i^avail < δ·L_i
满位临界：L_i − n_i < δ·L_i
```

- 搬运候选 = 缺车临界 ∪ 满位临界，且满足可达性；
- 发券候选 = 有可用车且非缺车临界（券用于把用户引向有车的点）；
- 无任何候选时，只能 wait。

### 7.4 奖励

```
r_t = −[ ω1·E_agent + ω2·E_env + ω3·T_truck + ω4·P_inc ] × reward_scale
```

各项先按 `cost.normalize` 的尺度归一化，再乘 `reward_scale`（默认 10）改善 PPO 梯度。

### 7.5 决策步长

10 min。依据：最短脉冲 20 min（P2/P5）；30 min 会把短课间与相邻平峰合并，抹平脉冲。

## 8. 评价指标（`src/bike_sched/metrics.py`）

| 指标 | 定义 | 来源 |
|---|---|---|
| 借车短缺 | `Σ e_i^b`（移步后仍未满足） | L1、L3 |
| 还车短缺 | `Σ e_i^r` | 本文（虚拟桩特有） |
| 搬运趟次 | 搬运动作次数 | L3 |
| 搬运作业时间 | `Σ τ` | L3 |
| 单位服务成本 | `(c_t·T_truck + 券支出) / 成功骑行次数` | L3 |

## 10. 简化与局限

| 简化 | 依据 | 影响 |
|---|---|---|
| 忽略还车时滞 | 校园骑行 < 10 min | 无实质影响 |
| 不刻画单车级电量 | 换电为外生固定作业 | 可能低估高峰可用车波动 |
| 换电路线与搬运路线不联合优化 | 需单车级电量数据 | 列为扩展 |
| 略去拥堵指数 | 校园无机动车拥堵 | 对 OD 影响小 |
| 车场库存不变 | 车场为集散点 | 夜间调度不改变车场库存 |
| 搬运当步末完成 | 10 min 步长、校园行程短 | 跨步在途为扩展 |
| SA 扰动策略参数而非动作序列 | 可运行性 | 论文须如实说明 |

主要局限：λ、VOT、γ 依赖 SP 问卷，反映陈述偏好而非真实行为；论文须区分"实测参数"与"标定参数"，并做敏感性分析。
