## 2. 表结构

### 2.1 `stations.csv`（P 点表）

| 列 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `id` | str | 是 | P 点编号 | P01 |
| `name` | str | 是 | 名称 | 笃行楼 |
| `lng` | float | 是 | 经度（GCJ-02） | 103.730369 |
| `lat` | float | 是 | 纬度（GCJ-02） | 36.111485 |
| `capacity` | int | 是 | 容量（辆） | 60 |
| `func` | str | 是 | 功能类别 | teach |
| `attraction` | float | 否 | 目的地吸引量 | 1.0 |
| `init_bikes` | int | 是 | 06:30 初始车辆数 | 45 |
| `target_bikes` | float | 否 | 夜间目标库存 | 30 |

`func` 取值：`dorm` / `teach` / `canteen` / `library` / `gate` / `sport` / `other`。

**容量估算**：`capacity ≈ 停车区面积 / 1.8 m²`（电动自行车含通道约 1.5–2.0 m²/辆）。用 `web/` 地图工具画停车区多边形可直接得到面积。

**吸引量**：默认取功能类别值（`configs/default.yaml → demand.function_attraction`）；有 POI 数或建筑面积时按比例替换。

### 2.2 `inventory_observations.csv`（在点车辆数）

| 列 | 类型 | 说明 |
|---|---|---|
| `time` | str | `HH:MM` |
| `station` | str | P 点编号 |
| `bikes` | int | 在点车辆数 |
| `note` | str | 满位、故障车、施工等 |

**采集粒度**：

- 七个脉冲窗口内：10 min 一张；
- 平峰：30–60 min 一张；
- 每日至少覆盖 06:30–23:30。

**采集方式**：7MA 小程序地图截图 → 逐点位计数。已提供 `tools/count_bikes.py` 的模板匹配思路（当前未纳入主仓库，可按需恢复）。

### 2.3 `od_observations.csv`（OD 观测）

| 列 | 类型 | 说明 |
|---|---|---|
| `time_window` | str | 如 `07:40-08:00` |
| `origin` | str | 起点 P 点 |
| `destination` | str | 终点 P 点 |
| `trips` | int | 人次 |
| `note` | str | 备注 |

**说明**：历史订单是供给约束下的观测值，会低估真实需求。OD 只用于标定**目的地选择参数**（吸引量、距离衰减），不直接当真实需求。

**替代方案**：若无法获得 OD，可用"车辆编号追踪法"（记录单车编号的起终点）或最大熵反推（8–12 个交通小区）。

### 2.4 `sp_survey.csv`（SP 问卷）

| 列 | 类型 | 说明 |
|---|---|---|
| `respondent_id` | str | 匿名编号 |
| `extra_walk_min` | float | 给定额外步行时间 |
| `continue_search` | 0/1 | 是否继续寻找 |
| `coupon_yuan` | float | 给定券额 |
| `switch_station` | 0/1 | 是否改去目标点 |
| `monthly_pass` | 0/1 | 是否月卡用户 |
| `vot_yuan_per_min` | float | 由无差异点反算 |

**样本量**：≥ 300 份有效问卷。

**标定方法**：

- λ：对 `continue_search ~ extra_walk_min` 做 Logistic 回归，`λ ≈ −β`；
- VOT：对"券额—步行时间"无差异点求均值；
- γ：`monthly_pass=0` 的比例。

## 3. 采集方案

### 3.1 点位与容量（1–2 天）

1. 用 `web/` 地图工具在高德底图上点选 P 点；
2. 画停车区多边形，自动得面积；
3. `capacity = round(area / 1.8)`，现场校正；
4. 记录功能类别与最近建筑名；
5. 导出 JSON → 转 `stations.csv`。

### 3.2 在点车辆数（精细日 2 天 + 常规日 4 天）

| 时段 | 频率 | 说明 |
|---|---|---|
| P1–P7 窗口 | 10 min | 最关键，必须覆盖 |
| 平峰 | 30–60 min | 可放宽 |
| 夜间 23:30 | 1 次 | 夜间调度初值 |

- 每日约 52 张截图（脉冲窗口 7×2–3 张 + 平峰 20–30 张）；
- 精细日 2 天 + 常规日 4 天 ≈ 184 张；
- 3 人轮班，1 人可完成单日。

### 3.3 运维车与换电（访谈）

- 车辆数、车型、载量 C；
- 作业频次与时间窗；
- 换电路线与单次换电时长；
- 单位作业成本 c_t。

### 3.4 成本参数（访谈 + 敏感性）

- 借车短缺损失 c_b（用户流失/投诉/调度触发成本）；
- 还车短缺损失 c_r；
- 若无法获得，按 `c_b : c_r : c_t = 3 : 2 : 1` 占位并做敏感性分析。

## 4. 数据质量检查

入库前必须通过：

- [ ] `stations.csv`：id 唯一、经纬度在校园范围内、capacity > 0；
- [ ] `inventory_observations.csv`：`0 ≤ bikes ≤ capacity`、时间在 06:30–23:30；
- [ ] 缺失率 < 10%；超过则补采；
- [ ] 同一时刻同一站点无重复记录；
- [ ] OD 行和与观测借车量偏差 < 15%；
- [ ] 距离矩阵：对角线为 0、对称、最大值 < 3 km。

代码检查脚本：

```bash
python scripts/check_data.py --data data/real
```

---

## 5. 缺失与异常处理

| 情况 | 处理 |
|---|---|
| 单点单时刻缺失 | 线性插值；脉冲窗口内不插值，标记为缺失 |
| 整日缺失 | 从训练集剔除，不补 |
| 满位导致计数偏小 | 记录 `note=full`，建模时按容量截断 |
| 故障车 | 从 `bikes` 中扣除，记录 `note=fault` |
| 极端天气 | 单独标记，不参与常规日训练 |
| 问卷无效 | 剔除（作答时间 < 30 s、全选同一项） |

## 6. 从地图工具 JSON 转 CSV

`web/` 导出的 JSON 结构：

```json
{
  "meta": {"campus": "...", "exportedAt": "...", "count": 12},
  "stations": [
    {"id": "P01", "name": "笃行楼", "lng": 103.73, "lat": 36.11,
     "capacity": 60, "func": "teach", "count": null}
  ]
}
```

转换脚本：

```bash
python scripts/json_to_stations.py --input web_export.json --output data/real/stations.csv
```

转换规则：

- `id/name/lng/lat/capacity/func` 直接映射；
- `init_bikes` 取首日 06:30 观测值；
- `target_bikes` 取容量 50% 或按次日 P1 需求；
- `attraction` 留空，由功能默认值填充。
